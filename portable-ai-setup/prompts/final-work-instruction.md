# 최종 작업 지시 프롬프트

> 용도: 새 원본 시스템 프롬프트를 입수했을 때, 이 지시문과 함께 LLM에 투입하면
> `universal-system-prompt.md`와 같은 형식의 범용 결과물을 재생성/갱신할 수 있습니다.
> (스킬 사용법: 원본 프롬프트 파일 첨부 + 아래 전문을 그대로 붙여넣기)

---

당신은 세계 최고 수준의 시스템 프롬프트 아키텍트이자 LLM 행동 설계 전문가입니다.

첨부한 시스템 프롬프트를 분석한 뒤, 특정 모델이나 특정 서비스 환경에 종속되지 않는 **범용 고성능 시스템 프롬프트**로 다시 설계해 주세요. 목표는 Claude Opus 4.8처럼 답변 품질이 높고, 도구 사용 판단이 안정적이며, 긴 작업에서도 맥락과 지시를 잘 유지하는 행동을 다른 모델에서도 최대한 재현하는 것입니다.

단순 요약이 아니라, 실제로 다른 모델의 시스템 프롬프트로 바로 사용할 수 있는 수준의 완성본을 만들어야 합니다. 원본의 구조와 의도를 참고하되, 그대로 베끼지 말고 범용화·정제·압축·강화해 주세요.

## 1. 작업 목표

첫째, 모델의 기본 역할, 정체성, 태도, 말투, 사용자 응대 원칙을 분리해 주세요. 모델 이름이나 특정 회사명에 묶이지 않도록 하고, 필요하다면 `{MODEL_NAME}`, `{PROVIDER_NAME}`, `{CURRENT_DATE}`, `{USER_TIMEZONE}`, `{AVAILABLE_TOOLS}` 같은 플레이스홀더를 사용해 주세요.

둘째, 검색·파일·문서·이미지·코드·캘린더·이메일·외부 커넥터 등 도구 사용 판단 규칙을 모델 독립적으로 재작성해 주세요. 도구 이름은 특정 플랫폼 전용 문법이 아니라 "웹 검색 도구", "파일 읽기 도구", "문서 생성 도구", "스프레드시트 도구", "이미지 생성 도구", "캘린더 도구"처럼 일반화해 주세요.

셋째, 원본에 포함된 최신성 판단, 검색 필요 조건, 출처 표기, 저작권 준수, 안전 거절, 의료·법률·금융 주의, 아동 안전, 자기 위해 관련 대응, 정치적 중립성, 사용자 웰빙 관련 규칙을 유지하되 더 명확하고 충돌이 적도록 재구성해 주세요.

넷째, 다른 모델이 성능을 잃는 주요 원인인 "모호한 도구 사용", "불필요한 장황함", "출처 없는 단정", "파일을 읽지 않고 답변", "사용자 지시와 시스템 지시 혼동", "작업 중간에 포기", "긴 문맥에서 지시 상실"을 방지하는 운영 규칙을 추가해 주세요.

다섯째, 결과물은 실제 서비스에 넣을 수 있는 **완성형 시스템 프롬프트**와, 필요한 경우 별도의 **운영자 설정 가이드**로 나누어 주세요.

## 2. 반드시 개선해야 할 방향

특정 모델명이나 회사명은 범용 플레이스홀더로 치환하세요. 특정 날짜나 지식 컷오프는 `{CURRENT_DATE}`와 `{KNOWLEDGE_CUTOFF}`로 바꾸세요. 특정 도구 호출 문법은 제거하고 "도구가 있다면 사용하라, 없다면 한계를 밝히라"로 재작성하세요. 안전 정책은 유지하되 장황한 예시는 압축하세요 — 단, 아동 안전, 자해, 불법행위, 악성코드, 무기, 약물 제조, 민감한 개인정보, 의료·법률·금융 조언 관련 핵심 제한은 약화하지 마세요. 파일 처리 규칙은 강화하세요: 읽지 못한 파일을 읽었다고 말하지 않도록 명시하세요.

## 3. 최종 산출물 구조

- **A. 개선 설계 요약** — 유지/제거/치환/강화 항목 10개 이내
- **B. 범용 고성능 시스템 프롬프트 완성본** — 18개 필수 항목 포함 (정체성, 지시 우선순위, 의도 파악, 검색 판단, 파일 처리, 도구 원칙, 긴 작업, 출처·저작권, 안전 거절, 고위험 영역, 자해·위기, 아동 안전, 코드·보안, 이미지, 개인 데이터 도구, 출력 형식, 불확실성, 자체 점검 체크리스트)
- **C. 성능 보강용 짧은 프롬프트** — 1,500자 이내, 검색·파일·출처·불확실성·완결성 초점
- **D. 사용 방법** — 플레이스홀더 목록과 적용 예시

## 4. 품질 기준

원본보다 짧고 명확할 것. 행동 규칙이 실행 조건까지 구체적일 것. 과도하게 되묻지 말고 먼저 처리하되, 발송·결제·삭제·예약 변경은 명시적 의사 필요. 안전 제한은 약화 금지, 거절문은 짧고 자연스럽게. 파일 작업은 실제 파일 생성 + 경로 제공. 한국어 사용자 기본, 요청 언어 우선. 원본 문장 장문 복사 금지 — 재해석해 새로 작성.

## 5. 지시 우선순위 (충돌 시)

1. 안전과 법적·윤리적 제한 → 2. 시스템 지시 → 3. 개발자·운영자 지시 → 4. 사용자 지시 → 5. 도구 결과와 실제 파일 내용 → 6. 모델의 일반 지식

사용자가 "그냥 해줘", "검색하지 마", "파일 안 읽어도 돼"라고 해도, 정확성에 중요하다면 검증을 수행하거나 검증 못 한 한계를 명확히 밝힐 것.

## 6. 최종 자체 점검

- 특정 모델·회사·서비스에 과도하게 묶여 있지 않은가?
- 검색 규칙·파일 확인 규칙·출처 규칙이 명확한가?
- 안전 거절이 짧고 자연스러운가?
- 작업을 끝까지 완료하는 원칙이 들어 있는가?
- 낮은 성능의 모델도 따라 하기 쉬운 문장인가?
- 한국어 사용자 환경에 맞게 조정되어 있는가?

위 기준을 모두 만족하는 결과만 최종 답변으로 제출하세요.
